### **Название задачи:** Актуальные ставки депозитов в кол-центре банка и у партнёра

### **Автор:** AlexCrush

### **Дата:** 04.11.2026

### **Функциональные требования**

Кейс добавляется в MVP открытия депозита и не заводит второй справочник ставок. Источник тот же сервис ставок, что в ADR задания 3. Персональные предложения туда уже умеют публиковать, но этому кейсу они не нужны.

В тексте задания API и SFTP стоят в одной фразе: партнёр не может делать API-вызовы, «например, через SFTP». SFTP вызовом API не является. Ниже SFTP — это канал, которым банк отдаёт файл. Партнёр банк по API не вызывает.

### **Нефункциональные требования**

| **№** | **Требование** |
| :-: | :- |
| 1 | Оба кол-центра читают ту же публикацию, что сайт. Второго реестра и почтового Excel для консультации нет. |
| 2 | Свой кол-центр получает ставку в момент запроса к сервису ставок. От АБС этот запрос не зависит. |
| 3 | Партнёр получает полный файл не реже раза в сутки и дополнительно после публикации. Суточная почтовая рассылка Excel этим не заменяется, но и секундной синхронности у файла нет. |
| 4 | Файл и экран своего кол-центра содержат только публичную линейку. Персональные предложения остаются в сервисе ставок для интернет-банка. |
| 5 | Канал до партнёра — SFTP, ключ, не API. Файл без клиентских данных. |
| 6 | Если сервис ставок не ответил, свой кол-центр показывает последний успешный ответ и его время, а не пустой экран и не ставку «из памяти оператора». Партнёр точно так же остаётся на последнем файле. |
| 7 | Повторная выкладка файла заменяет предыдущий снимок. Партнёр не склеивает дельту. |
| 8 | Доработка своего кол-центра — точечный Java-экран. Платформу подрядчика целиком не меняем. Партнёр — другая компания, не подрядчик этой платформы. |

### **Решение**

Диаграммы только про этот кейс:

- `c4-context.drawio` и `c4-context.png` — кто консультирует и откуда берёт ставку;
- `c4-components.drawio` и `c4-components.png` — компоненты сервиса ставок и системы кол-центра. Заявка, АБС и интернет-банк сюда не входят: для консультации по линейке они не нужны.

Свой кол-центр ходит в уже существующий в MVP сервис ставок за публичной линейкой. Отдельный API «для кол-центра» не заводим: это тот же чтение, которым пользуется сайт. Новый компонент у кол-центра один — экран ставок в карточке звонка. Его делает команда, которая и так точечно меняет платформу на Java. Если подрядчик платформы не пустит экран внутрь, оператор на время MVP открывает ту же линейку отдельной страницей сервиса ставок. Это хуже, второе окно, и в недостатки записано как запасной путь.

Партнёру API не отдаём. В сервисе ставок компонент экспорта собирает снимок публичной линейки и кладёт файл в SFTP-каталог банка. Система партнёра файл забирает сама по SFTP. Вызов в сторону банка — не API сервиса ставок, а чтение файла. Так читается фраза задания про файлы и невозможность API.

Персональные предложения лежат в той же базе сервиса ставок, но экспорт их не читает. Иначе ставка конкретного клиента уедет во внешнюю компанию.

Кто делает:

- команда интернет-банка — экспорт снимка и выкладка на SFTP, контракт файла;
- сопровождение своего кол-центра — экран ставок;
- IT — каталог SFTP и ключ партнёра;
- партнёр — загрузчик файла в своей системе;
- бэк-офис депозитов и кредитов процесс публикации не меняет.

### **Альтернативы**

Рассылать партнёру и своему кол-центру тот же Excel, которым ставки считают сегодня. Это текущий процесс, он как раз и расходится: письмо, чужая копия, нет даты на экране оператора. Сайт при этом читает сервис ставок. Три витрины снова разъедутся.

Дать партнёру тот же HTTPS, что своему кол-центру. В задании партнёр API не вызывает, система внешняя, и в этот канал нельзя выпускать персональные предложения. Файл с явной границей «только публичная линейка» этой ошибки не делает.

Копировать ставки в базу кол-центра ночной выгрузкой из АБС. АБС для витрины мы уже не читаем, а ночная копия отстаёт от сайта так же, как старый Excel. Свой кол-центр тогда консультирует не по той ставке, которую клиент видит на сайте.

Отправлять файл почтой вместо SFTP. Почта доставляет файл, но хуже проверяется, кто его забрал, и легче уезжает не туда. SFTP оставлен, потому что в задании назван именно он, хотя и в неверной связке со словом «API».

### **Недостатки, ограничения, риски**

Файл партнёра не мгновенный. Свой оператор уже видит новую ставку, партнёр ещё сидит на прошлом снимке, пока не заберёт файл. Поэтому на экране обоих обязательна дата публикации. Без неё расхождение незаметно.

SFTP для банка новый операционный контур. Сбой выкладки не гасит свой кол-центр и сайт: они читают сервис ставок напрямую. Гаснет только обновление партнёра, и он остаётся на последнем файле.

Экран в платформе подрядчика может не принять свою доработку. Запасной путь — страница сервиса ставок. Её не надо путать с выбранным решением.

Оператор не называет персональную ставку. Клиент, которому в интернет-банке показали индивидуальное предложение, по телефону услышит общую линейку. Это ограничение кейса: идентификации на звонке под персональную ставку здесь нет.

Партнёр и подрядчик своего кол-центра — разные компании. Срок файла у партнёра не связан со сроком экрана у своего кол-центра, на дорожной карте это две полосы.

### **Задачи по системам**

Крупные задачи для дорожной карты. Мелкие работы внутрь не раскладывал.

| Система | Задача | Когда относительно остального MVP |
| :- | :- | :- |
| Сервис ставок | Модель публичной линейки, публикация бэк-офисом, API чтения | Первым. Сайт, интернет-банк и оба кол-центра читают уже это |
| Сервис ставок | Экспорт снимка без персональных предложений и выкладка на SFTP | Сразу после API чтения. От заявок и АБС не зависит |
| Каталог SFTP | Каталог и ключ партнёра | Вместе с экспортом |
| Система кол-центра банка | Экран актуальных ставок по API сервиса ставок | После API чтения. Раньше приёма заявок с сайта: звонки начнутся с рекламы |
| Система партнёра | Загрузчик файла, полная замена предыдущего снимка, дата публикации на экране | После первой выкладки. Делает партнёр |
| Сервис заявок | Приём заявки с сайта и из интернет-банка | Параллельно с экраном ставок, это основной MVP, не этот кейс |
| Сайт | Витрина и форма заявки | После API ставок и сервиса заявок |
| Интернет-банк | Модуль «Депозиты» | После тех же API |
| АБС | Адаптер заявки в Oracle | После сервиса заявок |
| Система кол-центра банка | Карточка заявки с сайта | После сервиса заявок и после экрана ставок |
| SMS-шлюз | Тексты кода и статусов депозита | Вместе с сервисом заявок |
| Сервис ставок | Правила, по которым депозит открывается без ручного подтверждения | Уже после MVP, горизонт года |
| АБС | Открытие депозита адаптером без бэк-офиса, в отделении остаётся только фронт | После правил. Это целевое состояние года, не MVP |
| Кредитный контур | Заявка на кредит онлайн с решением за день | Отдельное решение, на этой карте только полоса срока. В задачи этого ADR не раскладывается |
